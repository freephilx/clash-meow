# 代理显示

本文记录 DouMeow 下载远程配置、解析节点并展示到代理页的策略。这里关注“配置里有哪些节点、节点组如何显示”，不包含代理测速规则；测速策略见 [代理测速](代理测速.md)。

## 问题

有些订阅服务会根据 `User-Agent` 返回不同格式：

1. Clash / Clash Meta 类 UA 返回 mihomo YAML，包含 `proxies`、`proxy-groups` 和 `rules`。
2. `mihomo` 或未知 UA 可能返回 base64 share links，例如 `vless://`、`ss://`、`anytls://`。
3. Surge 类 UA 会返回 Surge 配置，不能直接作为 mihomo YAML 使用。

如果只用 `mihomo/1.9.27` 请求远程配置，部分服务会返回 base64 share links。本项目虽然可以做有限归一化，但 share link 到 mihomo YAML 的转换很难覆盖所有协议细节；一旦归一化失败或解析不到 `proxies`，代理页就只剩默认的 `DIRECT`。

## 推荐策略

DouMeow 采用“默认单 UA 请求 + 失败时兼容降级 + share link 兜底”的策略。

1. 默认只请求一次，UA 使用 `DouMeow/<version> (clash.meta)`。
2. 默认 UA 明确表达“这是需要 Clash Meta / mihomo YAML 的客户端”，借鉴 clash-party 的 `mihomo.party/v版本 (clash.meta)` 写法，但保留 DouMeow 自身身份，不伪装成其他客户端。
3. 每次请求都记录等价 `curl -L --compressed -H ...` 到 `app.log`，包含实际 UA。
4. 对响应先归一化：
   - 原始 mihomo YAML 直接使用。
   - base64 后是 mihomo YAML，解码后使用。
   - 原文或 base64 后是 share links，仅作为兜底转换为最小 mihomo YAML。
5. 如果默认响应无法归一化、HTTP 状态异常、内容为空，或解析出的节点数为 0，再按备用 UA 降级重试：
   - `ClashMetaForAndroid/2.10.1`
   - `clash-verge/v1.7.7`
   - `clash.meta`
   - `ClashforWindows/0.20.39`
   - `ClashX Pro/1.118.1.1`
   - `mihomo/1.9.27`
6. 降级重试只用于异常订阅，不作为正常路径；默认 UA 已经得到有效节点时立即停止，避免每次刷新都浪费多次请求。
7. 如果所有 UA 都无法得到有效 mihomo YAML，则导入失败，不写入坏 Profile。
8. 代理页优先显示 mihomo controller `/proxies` 运行时数据；内核未启动或运行时数据缺失时，使用当前 Profile 的 `proxies` / `proxy-groups` 做离线预览。
9. 写回运行时配置时，Yams 必须开启 `allowUnicode`，避免把订阅原文里的中文和 emoji 转成 `\uXXXX` / `\UXXXXXXXX`。

## 代理页推荐方案

DouMeow 的代理页采用“运行时真相 + 配置顺序 + 模式解释”的方案：

1. **运行时优先**：mihomo controller 可达时，以 controller `/proxies` 为节点、当前选择、延迟、可用性的真相；App 只做 UI 分组和展示，不自行判断节点是否真的可用。
2. **配置顺序优先**：如果能从当前 runtime config 或 active Profile 读取 `proxy-groups` 顺序，代理页按配置里的 `proxy-groups` 顺序展示；controller 返回了配置里没有的可见组时，追加在末尾。
3. **过滤内置节点**：`DIRECT`、`REJECT`、`REJECT-DROP`、`PASS`、`COMPATIBLE` 等内置代理只作为组内选项展示，不作为独立节点组卡片展示。
4. **过滤 hidden 组**：controller 返回 `hidden: true` 的组默认不展示；后续如果需要排障，可在日志或开发开关中查看。
5. **模式解释清楚**：
   - direct 模式：代理页显示“直连模式”，不展示代理组。
   - rule 模式：展示配置里的普通策略组，默认隐藏 `GLOBAL`，因为规则流量不会直接由 `GLOBAL` 决定。
   - global 模式：展示 `GLOBAL` 并置顶，同时保留普通策略组，方便用户理解全局入口和底层策略组的关系。
6. **默认不追求与 Dashboard 完全一致**：mihomo dashboard 是 controller 原始视图；DouMeow 是面向日常使用的策略组视图。两者数量不同是允许的，但 DouMeow 必须能解释差异，并在 UI 中避免让用户误以为节点丢失。
7. **展开和搜索**：默认展开前几个可见组；提供组内搜索后，应自动展开匹配组。大节点组后续应使用虚拟列表或分页，避免一次渲染几百个节点导致 SwiftUI 卡顿。
8. **排序**：默认按配置顺序展示节点，保留用户订阅的语义；后续可增加“按延迟 / 按名称”切换，但不能替代默认配置顺序。
9. **离线预览**：controller 不可达时，使用 active Profile 的 `proxy-groups` / `proxies` 做只读预览；此时切换、测速按钮应提示“请先启动内核”。

## 代理页更新方案

1. **启动与进入页面**：App 启动、core 变为 healthy 时调用完整 `refresh()`；进入代理页时额外尝试读取 `/configs` 和 `/proxies`，只要 controller 可达就更新 `proxyGroups`、`proxyNodeStatuses` 和当前模式。
2. **轮询更新**：core healthy 时保持轻量轮询，刷新当前选择、延迟历史、alive 状态和新增/删除的组；core 停止时停止轮询，切回离线预览。
3. **切换代理**：点击组内节点时调用 `PUT /proxies/{group}`。成功后立即局部更新该组 `now`，再触发一次 controller refresh，避免 App 乐观状态与 mihomo 实际选择长期不一致。
4. **切换失败**：保留原选择，toast 提示失败，并记录日志；不能把 UI 先改成目标节点后不回滚。
5. **测速更新**：手动测速优先走 `/group/{group}/delay`，失败再逐节点 `/proxies/{proxy}/delay`；测速结果只更新当前组节点的 delay/alive，不改变组顺序和当前选择。
6. **配置切换或刷新订阅**：Profile 切换、远程配置刷新、runtime config 重写成功后，重新加载 active Profile 预览，再根据 core 状态刷新 controller 数据。
7. **连接处理**：代理切换后默认不主动关闭所有连接，避免破坏用户正在进行的网络任务；后续如果增加偏好项，可提供“切换代理后关闭连接”选项，借鉴 clash-party 的可配置策略。
8. **差异排查**：代理页与 `http://127.0.0.1:9090/ui/#/proxies` 不一致时，优先检查当前 mode、`hidden`、`GLOBAL` 展示规则、内置代理过滤、active Profile 与 runtime config 是否一致，而不是先怀疑订阅解析失败。

## 本项目取舍

优先使用 Clash Meta 类 UA，而不是只使用 `mihomo`，原因是：

1. 订阅服务通常把 Clash Meta / Clash 客户端识别为“需要 YAML”的客户端。
2. 原生 YAML 保留 `dns`、`proxy-groups`、`rules`、`proxy-providers` 和节点协议细节，远比本地 share link 转换可靠。
3. `mihomo` UA 在部分服务中会拿到 share links；它适合作为兜底，不适合作为第一优先级。
4. Surge UA 会拿到 Surge 配置，不适合作为 mihomo 默认请求 UA。
5. 正常路径只请求一次，避免浪费订阅服务请求次数；降级路径才多试几个常见 UA，避免疑难订阅直接掉成 `DIRECT`。

对 `https://moli.shy521.com/s/095ee97a3324fe02cbfb5bfff8892b9b` 的实测结果：

1. `mihomo/1.9.27` 返回 `text/plain` base64 share links。
2. `ClashMetaForAndroid/2.10.1`、`clash-verge/v1.7.7` 和 `clash.meta` 返回 `text/yaml` mihomo 配置。
3. `Surge Mac/2980` 返回 Surge `.conf`，不应作为本项目默认 UA。

因此本项目默认使用 `DouMeow/<version> (clash.meta)` 单次请求，并在异常时使用 Clash Meta 类备用 UA。日志会记录实际请求 UA、阶段和节点解析结果，方便排查“为什么只有 DIRECT”。

## 节点名称解码

远程订阅原文通常已经包含可读的中文、emoji 和其他非 ASCII 字符，不需要在下载阶段做额外解码。此前代理页出现 `\uXXXX` 的原因是本地用 Yams 读取、合并应用设置再写回 `config.yaml` 时，默认没有开启 `allowUnicode`，导致中文被序列化为 YAML 双引号转义，例如：

1. `\u5269\u4F59\u6D41\u91CF` 表示 `剩余流量`。
2. `\U0001F1ED\U0001F1F0` 表示 `🇭🇰`。

主修复是在生成运行时 YAML 时使用 `Yams.dump(..., allowUnicode: true)`，让 `config.yaml` 继续保持人类可读的中文和 emoji。代理页展示层仍保留 YAML 标量转义解码，只作为兼容旧版本已经写出的配置文件，或外部配置本身合法使用转义标量的情况。运行时从 mihomo API 返回的原始 `name` 仍保留用于代理切换和测速请求，UI 层使用独立的 `displayName` 展示，避免破坏 API 调用需要的原始名称。
