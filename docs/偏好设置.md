# 偏好设置

本文记录 clash-meow 建议放入“偏好设置”的用户可配置项。原则是：会影响用户日常体验、磁盘占用、排障方式或风险级别的选项，放到偏好设置；纯内部实现细节不暴露。

## 入口

1. 侧边栏“工具”分组提供“偏好设置”入口，使用齿轮图标并显示快捷键 `⌘,`。
2. 点击侧边栏入口或按下 `⌘,` 都打开独立的偏好设置窗口，不替换主窗口当前页面。

## 持久化位置

应用偏好持久化到 `~/.config/clash-meow/preferences.json`。

完整持久化清单见 [持久化](持久化.md)。

作用：

1. 记录 Clash Meow 自身的用户偏好，以及 `mihomoSettings` 下的当前 Profile、Profile 元数据、订阅信息和规则覆盖。
2. App 启动或打开偏好设置时从该文件读取。
3. 用户修改偏好时写回该文件。
4. 文件不存在或无法解析时使用默认偏好。

理由：

1. `~/.config/clash-meow/` 是 Clash Meow 的数据根目录；状态保存在根目录的 `preferences.json`，Profile 源 YAML 放入 `configs/mihomo/`，mihomo 工作数据放入 `runtime/mihomo/`，便于备份、查看和排障。
2. 文件内容直观，用户可以明确知道 App 最后保存了哪些设置。
3. `preferences.json` 是应用偏好的唯一数据源，避免多处来源互相覆盖。

`mihomoSettings` 的持久化结构包括：

1. `selectedProfileID`：当前 Profile ID。
2. `profiles`：每个 Profile 的名称、类型、远程 URL、更新时间、代理刷新设置和订阅流量信息。
3. `profiles[].ruleOverrides`：规则的 `prepend`、`append`、`delete` 覆盖。

`configs/mihomo/` 只保存源 YAML，不保存第二份选择或元数据状态。

## 窗口尺寸

偏好设置窗口应能容纳网络诊断 URL、日志筛选等较长设置项，不应使用过窄的固定宽度。

当前策略：

1. 默认窗口尺寸为 `640 x 720`。
2. 内容最小宽度为 `560`，最小高度为 `620`。
3. 窗口使用内容最小尺寸约束，允许用户继续拖拽放大。
4. 表单内容随窗口宽度自动排布，多行 URL 输入框可以随窗口变宽。

理由：

1. 互联网延迟诊断的公网测试 URL 支持多行，过窄窗口会造成阅读和编辑困难。
2. 日志和网络设置项会继续增长，固定小窗口会让偏好设置显得拥挤。
3. 允许缩放比继续加大固定尺寸更稳妥，能兼顾小屏和大屏。

## 内核

### 内核总开关

默认值：开启

作用：

1. 对应概览右上角总开关。
2. 开启时启动 mihomo 内核，并写入 `preferences.json` 的 `coreEnabled`。
3. 关闭时停止 mihomo 内核，并写入 `preferences.json` 的 `coreEnabled`。
4. 下一次打开 App 时读取 `coreEnabled`，决定是否恢复启动内核。
5. 启动中状态也属于用户已经打开总开关，UI 应显示为开启但暂时禁用。
6. 系统代理和 TUN 的恢复要等 mihomo controller 可用后再执行。

理由：

1. “内核总开关”表达的是当前 App 是否运行网络内核，比“自动启动”更贴近概览页右上角开关的含义。
2. 持久化最后一次用户确认的运行状态，可以让下一次启动恢复用户预期。

## 网络

网络设置用于记录系统接管能力最后一次成功应用后的正确状态，并在下一次启动时读取这些偏好。

### 管理员授权

默认行为：仅在需要释放被其它进程占用的监听端口时请求。

作用：

1. App 启动、重启或配置切换前，会检查 YAML 中声明的监听端口。
2. 如果端口没有被占用，不请求管理员授权。
3. 如果端口只被当前正在运行的 mihomo 占用，配置重载时会排除当前进程，不请求管理员授权。
4. 如果端口被当前用户可管理的旧进程占用，优先使用普通权限终止，不请求管理员授权。
5. 只有普通权限释放失败时，才通过 privileged helper 释放端口。
6. 如果 helper 安装授权被取消或失败，本次 App 会话会短时间暂缓重复请求，避免连续弹出密码窗口。

理由：

1. 管理员密码只应该用于确实需要更高权限的端口释放。
2. 开发调试或 helper 未正确安装时，重复弹窗会干扰用户操作。
3. 排除当前 mihomo 进程可以避免配置重载误判为端口冲突。

### 系统代理

默认值：关闭

作用：

1. 用户主动开启或关闭系统代理成功后，写入 `systemProxyUserEnabled` 和 `systemProxyEnabled`。
2. App 下一次启动后读取实际状态；内核总开关打开时按用户主动状态恢复。
3. 如果内核已经运行，则立即应用或关闭 macOS 系统代理。
4. 如果开启或关闭失败，或当前状态不允许开启，则显示 toast，并把开关、概览状态和偏好恢复到修改前的状态。
5. 内核总开关联动关闭系统代理时，只写 `systemProxyEnabled=false`，不覆盖 `systemProxyUserEnabled`。

理由：

1. 持久化值应表示 App 最后一次确认成功的真实状态，而不是一次失败的尝试。
2. 系统代理依赖本地 mixed-port，内核未运行时无法安全应用到系统网络设置。
3. 用户主动状态和实际状态分开，可以在关闭内核时安全关闭系统代理，又能在下次打开内核时恢复用户选择。
4. 失败时回滚 UI 和偏好，可以避免下一次启动读取到未成功应用过的状态。

### TUN 模式

默认值：关闭

作用：

1. 用户主动开启或关闭 TUN 成功后，写入 `tunUserEnabled` 和 `tunEnabled`。
2. App 下一次启动后读取实际状态；内核总开关打开时按用户主动状态恢复。
3. TUN 状态会通过 `RuntimeConfigBuilder` / `Yams` 结构化写入受控 runtime config，并优先通过 mihomo `PUT /configs?force=true` 热重载应用。
4. 内核总开关联动关闭 TUN 时，只写 `tunEnabled=false`，不覆盖 `tunUserEnabled`。
5. 用户主动开启 TUN 必须以内核已启动为前提；如果内核未启动，显示“请先启动内核”，并把开关和偏好恢复到修改前。
6. 如果启动 App 时内核总开关是关闭的，App 会把 `tunEnabled` 修正为关闭，但保留 `tunUserEnabled`。
7. 热重载后必须通过 `GET /configs` 校验运行时 `tun.enable` 和目标值一致。
8. 如果热重载失败、超时或校验不一致，会 fallback 到重启内核并再次校验。
9. fallback 重启或启动恢复时，mihomo 会通过 privileged helper 以 root 启动。
10. 如果重启后仍失败，App 会写回修改前的 runtime config，并把按钮、`tunEnabled`、`tunUserEnabled` 恢复到修改前。
11. TUN 应用过程中会抑制 App 自己写入 runtime config 触发的文件监听事件，避免授权或重启期间被误判为外部配置修改。

理由：

1. TUN 属于用户明确选择的流量接管方式，应跨重启保留。
2. runtime config 和 UI 偏好需要保持一致，避免下一次启动恢复到旧状态。
3. 用户主动状态和实际状态分开，可以在关闭内核时安全关闭 TUN，又能在下次打开内核时恢复用户选择。
4. TUN 是否真正可用取决于 mihomo 运行时是否加载到新配置，因此不能只把“结构化写入 runtime config 成功”当成最终成功。
5. macOS 上创建 `utun` 和配置路由需要更高权限；需要重启应用 TUN 时必须让 privileged helper 托管 core。

### 互联网延迟诊断

详细设计见 [互联网延迟](互联网延迟.md)。

默认值：

1. 公网测试 URL：
   - `https://www.apple.com/library/test/success.html`
   - `https://www.cloudflare.com/cdn-cgi/trace`
   - `https://github.com/`
2. DNS 测试域名：`bing.com`
3. 诊断超时：3 秒

作用：

1. 公网测试 URL 写入 `preferences.json` 的 `internetLatencyTestURLs`，支持逗号或换行分隔。
2. DNS 测试域名写入 `internetLatencyDNSDomain`。
3. 诊断超时写入 `internetLatencyTimeoutSeconds`，范围为 1 到 10 秒。
4. “互联网延迟”面板执行诊断时读取这些偏好。
5. 路由器延迟始终自动使用默认网关，不提供手动配置。

理由：

1. 不同网络环境对 Apple、Cloudflare、GitHub 等公网目标的可达性不同，测试 URL 应允许用户调整。
2. DNS 测试域名应允许用户选择更贴近自己网络环境的域名。
3. 超时时间影响诊断速度和弱网容忍度，适合放入偏好设置。
4. 默认网关是当前物理网络状态，不应由用户随意指定，否则会失去“路由器延迟”的诊断含义。

## 日志（历史方案）

当前实现已经改为与 douwork 一致的固定日志治理策略，偏好设置不再提供日志保留天数、文件大小、默认来源、默认级别、自动清理和清空入口。以下内容仅保留为早期设计记录，不代表当前产品行为；当前规则以 `docs/日志.md` 为准。

日志设置用于控制日志保留、文件大小和日志页默认行为。

日志时间不单独提供偏好项：写入和展示都自动使用本机当前时区。日志文件会保留 `+08:00` 这类时区偏移，方便排障；日志页展示为 `yyyy-MM-dd HH:mm:ss`，避免把偏移误读成具体时间。用户修改系统时区后，新的日志写入会跟随新的本机时区；历史日志页会把可解析的 ISO8601 时间按当前本机时区展示。

### 日志保留天数

默认值：7 天

建议范围：1 到 30 天

作用：

1. App 启动时清理超过保留天数的旧日志。
2. 未超过保留天数的日志，重启 App 后仍然保留。

理由：

1. 7 天足够覆盖大多数问题回溯。
2. 避免长期运行后日志无限占用磁盘。
3. 允许高级用户根据排障习惯调大或调小。

### 单文件大小上限

默认值：10MB

建议范围：1MB 到 100MB

作用：

1. 限制单个日志文件大小。
2. 文件超过上限时保留最近内容，截断较早内容。
3. 截断时写入标记，方便识别日志不完整。

建议标记：

```text
[LOG] File truncated because size limit reached.
```

理由：

1. mihomo 在 debug 或异常场景下可能产生大量日志。
2. 单文件上限能避免打开、复制、上传日志时卡顿。
3. 保留尾部内容通常更有排障价值。

### 记录应用日志

默认值：开启

作用：

1. 开启时写入 `app.log`。
2. 记录 clash-meow 自身事件，例如启动、停止、配置切换、端口释放、helper 调用、WebSocket 重连。
3. 关闭后只保留 mihomo core 日志。

理由：

1. 应用日志能判断问题发生在 UI/控制层还是 mihomo 内核。
2. 少数用户可能希望减少本地日志写入，因此保留关闭入口。

### 日志页默认来源

默认值：`core`

可选值：

1. `core`
2. `app`
3. `all`

作用：

1. 控制打开日志页时默认展示哪类日志。
2. `core` 展示 mihomo 相关日志。
3. `app` 展示 clash-meow 自身日志。
4. `all` 合并展示。

理由：

1. 普通用户多数时候关心代理内核日志，默认 `core` 更直接。
2. 开发和排障时可以切到 `app` 或 `all`。

### 日志页默认级别

默认值：跟随当前 mihomo `log-level`

可选值：

1. 跟随配置
2. `debug`
3. `info`
4. `warning`
5. `error`

作用：

1. 控制实时跟随 `/logs?level=...` 时使用的默认级别。
2. 不影响已经写入文件的历史日志。

理由：

1. 跟随配置符合用户当前运行设置。
2. 排障时可以临时切到更详细的级别。

### 启动时自动清理过期日志

默认值：开启

作用：

1. App 启动时按“日志保留天数”清理旧日志。
2. 只清理 clash-meow 自己的日志文件。

理由：

1. 自动清理能保持磁盘占用稳定。
2. 只在启动时执行，逻辑简单，用户也容易理解。

### 清空日志文件

默认值：显示入口，但必须二次确认

作用：

1. 清空当前选中来源对应的日志文件。
2. 与“清空视图”分开。
3. 清空后重启 App 也无法恢复被清掉的内容。

理由：

1. 用户有时需要清理旧日志后重新复现问题。
2. 这是破坏性操作，必须明确确认。

## 日志设置建议落点

建议在偏好设置中新增“日志”分组，包含：

1. 日志保留天数
2. 单文件大小上限
3. 记录应用日志
4. 日志页默认来源
5. 日志页默认级别
6. 启动时自动清理过期日志
7. 显示清空日志文件入口

日志页本身只保留即时操作：

1. 来源筛选
2. 级别筛选
3. 搜索
4. 跟随/暂停
5. 刷新
6. 清空视图
7. 打开日志文件
8. 在 Finder 中显示
9. 清空日志文件
