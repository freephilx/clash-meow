# 持久化

本文记录 DouClash 所有会跨启动保留的数据、存放位置和约束。

## 总原则

DouClash 自己管理的持久化数据统一放在：

```text
~/.config/dou-clash/
  preferences.json
  configs/
    mihomo/
      default.yaml
      <id>.yaml
  runtime/
    diagnostic-reports/
      DouClash-Network-Diagnostics-<timestamp>.zip
    logs/
      app.log
    mihomo/
      config.yaml
      mihomo.log
      cache.db
      GeoData...
```

理由：

1. 该目录是 DouClash 的数据根目录；用户输入与可再生 runtime 数据分层存放，便于备份、查看和排障。
2. 文件形式直观，用户可以直接查看最后保存的状态。
3. 代码侧只应通过统一路径定义获取根目录，避免不同模块写出多个配置目录。

## 路径定义

代码入口：

1. `AppPersistencePaths.configDirectory`
   - 返回 `~/.config/dou-clash/`。
   - App 内新增持久化文件时应优先从这里派生路径。
2. `AppPersistencePaths.configsDirectory`
   - 指向 `~/.config/dou-clash/configs/`。
3. `AppPersistencePaths.mihomoConfigsDirectory`
   - 指向 `~/.config/dou-clash/configs/mihomo/`。
   - 只保存 Profile 原始 YAML；当前选择、Profile 元数据和规则 override 均保存在 `preferences.json`。
4. `AppPersistencePaths.runtimeDirectory`
   - 指向 `~/.config/dou-clash/runtime/`。
   - 保存可再生配置、日志和进程运行数据。
5. `AppPersistencePaths.mihomoRuntimeDirectory`
   - 指向 `~/.config/dou-clash/runtime/mihomo/`。
   - 也是 `MihomoCoreManager.configDirectory`，mihomo 启动时作为 `-d` 工作目录。
6. `AppPersistencePaths.logsDirectory`
   - 指向 `~/.config/dou-clash/runtime/logs/`。
7. `AppPersistencePaths.diagnosticReportsDirectory`
   - 指向 `~/.config/dou-clash/runtime/diagnostic-reports/`。
   - 保存用户主动生成的本地网络诊断 ZIP。
8. `AppPreferenceStore.preferencesFile`
   - 指向 `~/.config/dou-clash/preferences.json`。

## 应用偏好

路径：

```text
~/.config/dou-clash/preferences.json
```

内容：

1. `coreEnabled`：概览右上角“内核总开关”的持久化状态；打开 App 时是否恢复启动内核。
2. `systemProxyUserEnabled`：用户最后一次主动设置的系统代理状态。
3. `systemProxyEnabled`：系统代理当前最后一次成功应用后的实际状态。
4. `tunUserEnabled`：用户最后一次主动设置的 TUN 状态。
5. `tunEnabled`：TUN 当前最后一次成功应用后的实际状态。
6. `mihomoSettings.selectedProfileID`：当前 Profile ID。
7. `forwardingMode`：出站模式选择。
8. `allowLan`：是否允许局域网访问。
9. `systemProxyNetworkService`：最近成功应用系统代理的 macOS 网络服务名。
10. 互联网延迟诊断设置：公网测试 URL、DNS 测试域名、诊断超时时间。
11. `launchAtLogin`：登录时打开的用户偏好。
12. `mihomoSettings.profiles`：Profile 名称、类型、订阅 URL、更新时间、代理刷新设置、订阅流量信息和 `ruleOverrides`。

规则：

1. 新写入统一落到 `preferences.json`。
2. 文件不存在或无法解析时使用默认偏好。
3. 持久化值应表示 App 最后确认成功的状态；失败或不允许应用的操作需要回滚 UI 和持久化值。
4. 内核总开关联动关闭系统代理或 TUN 时，只更新实际状态字段，不覆盖用户主动设置字段。
5. 再次打开内核总开关时，按用户主动设置字段恢复系统代理和 TUN。
6. Profile 的 runtime config 成功生成后才写入 `mihomoSettings.selectedProfileID`；启动时按该字段恢复当前配置。
7. 如果 `mihomoSettings.selectedProfileID` 指向的 Profile 已不存在，则回退到 `default` 并写回该字段。
8. macOS 登录项和系统代理本身属于系统状态，无法放进配置目录；DouClash 只把自己的期望值或最后成功状态记录在 `preferences.json`。

## mihomo 运行配置

路径：

```text
~/.config/dou-clash/runtime/mihomo/config.yaml
```

用途：

1. mihomo 启动时使用的实际配置文件。
2. 首次启动如果不存在，会从 App 内置 `sampleConfig.yaml` 创建。
3. 当前 Profile 切换后，会通过 `RuntimeConfigBuilder` 把 Profile 原文和 App 受控设置合成为 runtime config，再写入该文件。
4. TUN 等需要写入 YAML 的配置会通过结构化 YAML 写入修改该文件。

规则：

1. `config.yaml` 是运行时活动配置，不直接代表 Profile 元数据。
2. Profile 原始内容应保存在 `configs/mihomo/` 下；切换 Profile 时再生成受控 runtime config 到 `runtime/mihomo/config.yaml`。
3. `config.yaml` 中的端口、controller、mode、log-level、`find-process-mode`、TUN 等 App 受控字段由 `RuntimeConfigBuilder` 覆盖，订阅原文不能覆盖这些运行时关键字段；其中 `find-process-mode` 固定为 `always`，`allow-lan` 暂时继承 Profile。

## Profile 数据

目录：

```text
~/.config/dou-clash/configs/mihomo/
```

文件与状态：

1. `<id>.yaml`
   - 每个 Profile 的原始 YAML。
   - 本地导入、远程订阅、空白配置都会写成独立 YAML。
2. `preferences.json.mihomoSettings.selectedProfileID`
   - 唯一的当前 Profile ID。
   - 切换成功或缺失配置回退时更新。
3. `preferences.json.mihomoSettings.profiles`
   - Profile 名称、类型、本地或远程来源、订阅 URL、更新时间、是否通过代理刷新、订阅流量信息。
   - 远程订阅如果返回 `Subscription-Userinfo`，保存其中的 `upload`、`download`、`total`、`expire`。
   - 每个 Profile 的 `ruleOverrides` 保存 `prepend`、`append`、`delete` 规则覆盖。
   - 配置文件页面读取该元数据，显示“已用流量 / 总流量 · 百分比”、流量进度条和到期时间；没有订阅流量头的配置不展示用量区，避免把未知值显示成 `0`。

规则：

1. Profile ID 是文件级持久化单位。
2. 删除 Profile 时删除对应 YAML，并同步更新 `mihomoSettings.profiles`。
3. 当前 Profile 被删除后，选择列表里的下一个 Profile 并写回 `mihomoSettings.selectedProfileID`。
4. 默认 Profile 不允许删除，缺失时由 App 自动补齐。
5. `configs/mihomo/` 不保存 `current.txt`、`profiles-metadata.json` 或 `<id>.rules.yaml`；这些旧文件即使存在也不会被读取、改写或迁移。

## 日志

路径：

```text
~/.config/dou-clash/runtime/logs/app.log
~/.config/dou-clash/runtime/logs/app-<timestamp>.log
~/.config/dou-clash/runtime/mihomo/mihomo.log
```

文件：

1. `runtime/mihomo/mihomo.log`
   - mihomo stdout/stderr。
   - 以追加方式写入，不添加 App 自定义 session header。
2. `runtime/logs/app.log`
   - DouClash 自身应用日志。
   - 启动时轮转为带时间戳的归档文件。

规则：

1. 应用日志文件跨 App 重启保留，但日志页只展示当前会话应用日志。
2. `app.log` 固定上限 10 MiB，超限后保留最近约 5 MiB；单行最多 64 KiB。
3. 最多保留 9 个应用日志归档，加上当前文件共 10 个。
4. Mihomo 历史日志只从文件尾部扫描最多 1 MiB，并过滤为当前 App 会话。
5. 日志时间按本机时区写入和展示。

## 网络诊断报告

路径：

```text
~/.config/dou-clash/runtime/diagnostic-reports/
  DouClash-Network-Diagnostics-<timestamp>.zip
```

规则：

1. 只有用户在健康检查页面明确点击“开始网络诊断”后才生成报告。
2. 目录权限为 `0700`，ZIP 与临时报告文本权限为 `0600`。
3. 最多保留最近 5 份 DouClash 诊断 ZIP。
4. 报告只包含有界且脱敏的运行摘要、系统网络现场和近期日志，不保存配置或偏好文件。
5. 取消、失败或完成后清理 staging 目录；报告不会被自动上传。

完整行为见[网络诊断报告](网络诊断.md)。

## mihomo 工作目录数据

mihomo 使用 `~/.config/dou-clash/runtime/mihomo/` 作为 `-d` 工作目录，因此内核或 Web UI 可能在该目录下生成或读取运行数据，例如：

```text
~/.config/dou-clash/runtime/mihomo/cache.db
~/.config/dou-clash/runtime/mihomo/ui/
~/.config/dou-clash/runtime/mihomo/geoip.dat
~/.config/dou-clash/runtime/mihomo/geosite.dat
~/.config/dou-clash/runtime/mihomo/country.mmdb
~/.config/dou-clash/runtime/mihomo/ASN.mmdb
```

规则：

1. 这些文件属于 mihomo 运行数据或资源数据，统一限制在 `runtime/mihomo/`。
2. DouClash 不应把 mihomo 工作数据写到 `~/Library/Application Support`、`~/Library/Caches` 或其它散落目录。

## 临时数据

以下数据不属于持久化数据：

1. UI 内存状态，例如实时日志列表、连接列表、流量历史。
2. `/tmp` 下的临时脚本、测试文件、截图文件。
3. Debug 或测试模式下显式指定的临时输出路径。

规则：

1. 临时数据可以使用系统临时目录。
2. 临时数据不得作为 App 下一次启动恢复状态的来源。

## 新增持久化项要求

新增任何跨启动保留的数据时，需要同时满足：

1. 路径必须位于 `~/.config/dou-clash/` 下。
2. 代码路径从 `AppPersistencePaths.configDirectory` 派生。
3. 如果是用户偏好，加入 `preferences.json`，不要新增其他偏好数据源。
4. Mihomo Profile 等用户输入统一放入 `configs/mihomo/`；日志和 mihomo 工作数据统一放入 `runtime/`。
5. 同步更新本文档和相关功能文档。
