# 持久化

本文记录 Clash Meow 所有会跨启动保留的数据、存放位置和约束。

## 总原则

Clash Meow 自己管理的持久化数据统一放在：

```text
~/.config/clash-meow/
```

理由：

1. 该目录同时是 mihomo 的工作目录，App、配置、日志和运行缓存放在同一根目录下，便于备份、查看和排障。
2. 文件形式直观，用户可以直接查看最后保存的状态。
3. 代码侧只应通过统一路径定义获取根目录，避免不同模块写出多个配置目录。

## 路径定义

代码入口：

1. `AppPersistencePaths.configDirectory`
   - 返回 `~/.config/clash-meow/`。
   - App 内新增持久化文件时应优先从这里派生路径。
2. `MihomoCoreManager.configDirectory`
   - 使用 `AppPersistencePaths.configDirectory`。
   - mihomo 启动时作为 `-d` 工作目录。
3. `AppPreferenceStore.preferencesFile`
   - 指向 `~/.config/clash-meow/preferences.json`。

## 应用偏好

路径：

```text
~/.config/clash-meow/preferences.json
```

内容：

1. `coreEnabled`：概览右上角“内核总开关”的持久化状态；打开 App 时是否恢复启动内核。
2. `systemProxyUserEnabled`：用户最后一次主动设置的系统代理状态。
3. `systemProxyEnabled`：系统代理当前最后一次成功应用后的实际状态。
4. `tunUserEnabled`：用户最后一次主动设置的 TUN 状态。
5. `tunEnabled`：TUN 当前最后一次成功应用后的实际状态。
6. `selectedProfileID`：用户最后一次主动选择或导入后自动选中的 Profile ID。
7. `forwardingMode`：出站模式选择。
8. `allowLan`：是否允许局域网访问。
9. `systemProxyNetworkService`：最近成功应用系统代理的 macOS 网络服务名。
10. 日志设置：保留天数、单文件大小、默认来源、默认级别、是否记录应用日志、是否自动清理、是否显示清空入口。
11. 互联网延迟诊断设置：公网测试 URL、DNS 测试域名、诊断超时时间。
12. `launchAtLogin`：登录时打开的用户偏好。

规则：

1. 新写入统一落到 `preferences.json`。
2. 文件不存在或无法解析时使用默认偏好。
3. 持久化值应表示 App 最后确认成功的状态；失败或不允许应用的操作需要回滚 UI 和持久化值。
4. 内核总开关联动关闭系统代理或 TUN 时，只更新实际状态字段，不覆盖用户主动设置字段。
5. 再次打开内核总开关时，按用户主动设置字段恢复系统代理和 TUN。
6. 用户主动选择 Profile 或导入 Profile 后自动选中新 Profile 时，写入 `selectedProfileID`；启动时优先按该字段恢复当前配置。
7. 如果 `selectedProfileID` 指向的 Profile 已不存在，则清空该字段，不继续引用失效配置。
8. macOS 登录项和系统代理本身属于系统状态，无法放进配置目录；Clash Meow 只把自己的期望值或最后成功状态记录在 `preferences.json`。

## mihomo 运行配置

路径：

```text
~/.config/clash-meow/config.yaml
```

用途：

1. mihomo 启动时使用的实际配置文件。
2. 首次启动如果不存在，会从 App 内置 `sampleConfig.yaml` 创建。
3. 当前 Profile 切换后，会通过 `RuntimeConfigBuilder` 把 Profile 原文和 App 受控设置合成为 runtime config，再写入该文件。
4. TUN 等需要写入 YAML 的配置会通过结构化 YAML 写入修改该文件。

规则：

1. `config.yaml` 是运行时活动配置，不直接代表 Profile 元数据。
2. Profile 原始内容应保存在 `profiles/` 下；切换 Profile 时再生成受控 runtime config 到 `config.yaml`。
3. `config.yaml` 中的端口、controller、mode、allow-lan、log-level、TUN 等 App 受控字段由 `RuntimeConfigBuilder` 覆盖，订阅原文不能覆盖这些运行时关键字段。

## Profile 数据

目录：

```text
~/.config/clash-meow/profiles/
```

文件：

1. `<id>.yaml`
   - 每个 Profile 的原始 YAML。
   - 本地导入、远程订阅、空白配置都会写成独立 YAML。
2. `current.txt`
   - 当前 Profile ID。
   - 切换 Profile 时更新。
   - 表示当前实际生效的 Profile。
3. `profiles-metadata.json`
   - Profile 名称、类型、本地或远程来源、订阅 URL、更新时间、是否通过代理刷新、订阅流量信息。
   - 远程订阅如果返回 `Subscription-Userinfo`，保存其中的 `upload`、`download`、`total`、`expire`。
   - 配置文件页面读取该元数据，显示“已用流量 / 总流量 · 百分比”、流量进度条和到期时间；没有订阅流量头的配置不展示用量区，避免把未知值显示成 `0`。

规则：

1. Profile ID 是文件级持久化单位。
2. 删除 Profile 时删除对应 YAML，并同步更新 metadata。
3. 当前 Profile 被删除后，选择列表里的下一个 Profile 并写回 `current.txt`。
4. 默认 Profile 不允许删除，缺失时由 App 自动补齐。
5. `preferences.json` 的 `selectedProfileID` 表示用户最后一次主动选择，不等同于自动兜底产生的 `current.txt`。

## 日志

目录：

```text
~/.config/clash-meow/logs/
```

文件：

1. `core.log`
   - mihomo stdout/stderr。
   - 每次启动追加 session header。
2. `app.log`
   - Clash Meow 自身应用日志。
   - 受“记录应用日志”偏好控制。

规则：

1. 日志跨 App 重启保留。
2. 启动时按日志偏好清理过期文件。
3. 单文件超过上限时保留尾部内容并写入截断标记。
4. 日志时间按本机时区写入和展示。

## mihomo 工作目录数据

mihomo 使用 `~/.config/clash-meow/` 作为 `-d` 工作目录，因此内核或 Web UI 可能在该目录下生成或读取运行数据，例如：

```text
~/.config/clash-meow/cache.db
~/.config/clash-meow/ui/
~/.config/clash-meow/geoip.dat
~/.config/clash-meow/geosite.dat
~/.config/clash-meow/country.mmdb
~/.config/clash-meow/ASN.mmdb
```

规则：

1. 这些文件属于 mihomo 运行数据或资源数据，也应保留在同一根目录下。
2. Clash Meow 不应把 mihomo 工作数据写到 `~/Library/Application Support`、`~/Library/Caches` 或其它散落目录。

## 临时数据

以下数据不属于持久化数据：

1. UI 内存状态，例如实时日志列表、连接列表、流量历史。
2. `/tmp` 下的临时脚本、测试文件、截图文件。
3. Debug 或测试模式下显式指定的临时输出路径。

规则：

1. 临时数据可以使用系统临时目录。
2. 临时数据不得作为 App 下一次启动恢复状态的来源。

## 新增持久化项要求

新增任何跨启动保留的数据时，需要同时满足：

1. 路径必须位于 `~/.config/clash-meow/` 下。
2. 代码路径从 `AppPersistencePaths.configDirectory` 派生。
3. 如果是用户偏好，加入 `preferences.json`，不要新增其他偏好数据源。
4. 如果是 Profile、日志或 mihomo 工作数据，应放入对应子目录。
5. 同步更新本文档和相关功能文档。
