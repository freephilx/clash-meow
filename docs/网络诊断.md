# 网络诊断报告

本文记录“健康检查”页面右上角“网络诊断”的交互、报告内容和隐私边界。概览页“互联网延迟”卡片中的“诊断”仍然只展示即时延迟明细，不生成文件。

## 交互流程

点击“网络诊断”后打开独立 sheet。初始页面不会自动读取或写入报告；用户点击“开始网络诊断”后，应用依次：

1. 重新检查公网 HTTP、默认网关、DNS、代理链和本地 Mihomo Controller。
2. 读取系统代理、本机 DNS 和当前运行状态。
3. 有界收集当前 App、Mihomo 日志及最近 3 份符合固定命名规则的归档。
4. 采集可见的 Mihomo、Clash 进程和系统 DNS 现场。
5. 对运行摘要、进程命令行、DNS 信息和日志执行脱敏。
6. 生成 `report.txt`、`app.log` 和 `mihomo.log`，再压缩为 ZIP。

sheet 分阶段展示准备、网络检查、日志收集、报告生成和压缩进度。关闭或取消 sheet 会取消正在执行的任务并清理临时目录；失败时在同一 sheet 内显示错误并提供重试。

完成后，“查看诊断报告”只通过 Finder 选中 ZIP，不自动上传或发送任何内容。

## 保存位置

```text
~/.config/dou-meow/runtime/diagnostic-reports/
  DouMeow-Network-Diagnostics-<timestamp>.zip
```

目录权限为 `0700`，报告文本和 ZIP 权限为 `0600`。只保留最近 5 份 DouMeow 诊断报告；生成失败或取消时清理隐藏的 staging 目录和不完整 ZIP。

## 报告内容

`report.txt` 包含：

- DouMeow、macOS 和芯片架构信息。
- Mihomo 状态、版本、当前 Profile、TUN、Controller、系统代理和本机 DNS 摘要。
- 公网、默认网关、DNS 和代理链诊断结果。
- 系统进程表中可执行文件名包含 `mihomo` 或 `clash` 的进程及脱敏后的状态和命令行；DouMeow 管理的 Mihomo 会单独标记。
- 全部网络服务的 DNS 服务器与搜索域、`scutil --dns`、`/etc/resolv.conf` 和 `/etc/resolver` 的当前内容。
- 当前内存中最近 10 条错误摘要。

`app.log` 和 `mihomo.log` 每个源文件最多读取尾部 500 行；每类合并结果不超过 2 MiB。只读取当前日志和最近 3 份固定格式的普通归档文件，符号链接、其他文件和更早归档不会进入报告。

## 隐私边界

网络诊断不会读取或打包：

- Mihomo 源配置或 runtime YAML。
- `preferences.json` 和订阅元数据。
- 完整日志或无限量历史归档。
- 任何需要上传到外部服务的数据。

写入报告前会脱敏 Bearer、API Key、Token、Secret、Cookie、密码、URL 用户信息、敏感查询参数、常见敏感命令参数和 `/Users/<name>` 主目录路径。进程名、网络服务名、DNS 地址和域名仍可能作为排障现场保留，用户应在发送 ZIP 前确认接收方可信。

## 设计来源

交互流程、文件结构、有界日志、脱敏、权限、保留数量和 Finder 定位行为参考 DouWork 的网络诊断报告实现；DouMeow 只保留与本地 mihomo 客户端相关的检查项，不包含 DouWork 的公司隧道、公司代理、公司 DNS 或 OpenVPN 专用诊断。
